# zyf-video — ComfyUI 视频处理插件

zyf-video 是一套 ComfyUI 视频处理节点，提供视频加载、信息解包和视频保存三大功能。

**核心特性：**

- 节点内直接预览视频，拖拽时间轴选取帧范围
- 播放控制：播放/暂停、逐帧前进/后退、跳转、设置入出点
- 自由裁剪：在预览画面上拖拽选区，所见即所得
- 强制尺寸缩放：多种预设分辨率 + 自定义短边/长边/宽高
- 强制帧率重映射：按目标帧率重新抽帧，音频自动同步拉伸
- H.264 / H.265 编码输出，CRF 质量控制，工作流元数据嵌入
- **分段计划**：长视频自动分段 → 队列逐段处理 → 自动合并，单段显存可控
- **参数折叠面板**：节点右上角按钮折叠/展开参数，状态持久化记忆

---

## 节点概览

| 节点名称 | 功能 |
|---------|------|
| **zyf加载视频** | 加载视频文件（或图像批），提供时间轴预览、入/出点选取、帧间隔、强制尺寸、自由裁剪、分段计划等 |
| **zyf视频信息解包** | 将 zyf加载视频 输出的复合视频信息包拆分为独立的数值端口 |
| **zyf保存视频** | 将图像批编码为 H.264/H.265 MP4 视频，支持分段自动合并、元数据嵌入、子文件夹输出 |

---

## 1. zyf加载视频

核心节点，负责加载视频源并输出帧和音频到下游处理。

### 参数面板

节点右上角有 **折叠/展开按钮**（默认折叠），点击可展开/收起参数设置，折叠状态随工作流记忆保存。

展开后参数顺序（从上到下）：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| **开始帧** | INT | -1 | 入点帧号（-1 = 首帧）。也可通过时间轴绿色标记或"设入点"按钮设置 |
| **结束帧** | INT | -1 | 出点帧号（-1 = 尾帧）。也可通过时间轴红色标记或"设出点"按钮设置 |
| **强制帧率** | FLOAT | 0.0 | 强制重映射帧率（0 = 沿用原视频帧率）。启用后按 `原视频时长 × 强制帧率` 计算总帧数，从原始视频均匀抽帧映射到新时间轴，音频时长自动同步拉伸。范围 0-60 |
| **帧间隔** | INT | 1 | 每隔 N 帧取一帧（预留抽帧设置，当前为 UI 指示，改值后时间轴显示同步更新） |
| **强制尺寸** | 下拉 | 禁用 | 视频帧缩放选项（见下方表格） |
| 自定义短边 | INT | 480 | 仅"自定义短边"时生效，短边目标像素值（0-8192，步长8） |
| 自定义长边 | INT | 832 | 仅"自定义长边"时生效，长边目标像素值（0-8192，步长8） |
| 自定义宽度 | INT | 480 | 仅"自定义宽高"时生效，宽度目标像素值（填 0 表示等比缩放） |
| 自定义高度 | INT | 832 | 仅"自定义宽高"时生效，高度目标像素值（填 0 表示等比缩放） |
| 图像尺寸倍数 | 下拉 | 32 | 输出尺寸向下取整到指定倍数（无/8/16/32/64/128/256/512），用于 VAE 编码兼容性 |
| **分段计划** | 下拉 | 禁用 | 禁用 / 启用。启用后将选中区间按分段长度拆分为多段，每次队列运行导出对应段，最后自动合并 |
| 分段长度 | INT | 81 | 每段帧数（最低 41，最高 99999）。WAN 推荐 4N+1，LTX 推荐 8N+1。widget 右侧实时显示"共 X 段" |
| 分段索引 | INT | 0 | 当前要导出的分段索引（从 0 开始）。自动排队模式下由系统递增，手动模式下自行设置 |
| **裁剪X/Y/W/H** | FLOAT | 隐藏 | 自由裁剪参数（0-1 归一化），由裁剪工具自动设置，通常无需手动调整 |

> **视频路径**始终显示在折叠按钮上方（连接 images 输入时自动隐藏），支持直接拖拽视频文件到节点或点击文件夹图标上传。

### 强制尺寸选项

| 选项 | 效果 |
|------|------|
| 禁用 | 保持原始尺寸 |
| 自定义短边 | 短边对齐目标值，长边等比缩放 |
| 自定义长边 | 长边对齐目标值，短边等比缩放 |
| 自定义宽高 | 直接指定宽/高，填 0 则该边等比 |
| 480x? / ?x480 | 宽/高对齐 480，另一边等比 |
| 832x? / ?x832 | 宽/高对齐 832，另一边等比 |
| 480x480 / 832x832 | 固定正方形 |

### 时间轴与播放控制

- **时间轴滑块**：拖拽定位当前帧，入点（绿色标记）和出点（红色标记）直观显示选中范围
- **播放控制按钮**（从左到右）：跳首帧、上一帧、设入点、播放/暂停、设出点、下一帧、跳尾帧、逐帧后退、逐帧前进
- **原视频帧率指示**：强制帧率 widget 旁以灰色小字显示原视频帧率，方便对比
- **自由裁剪**：点击裁剪按钮后在预览画面上拖拽选区，选区可拖动/缩放，所见即所得

### 输入端口

| 端口 | 类型 | 说明 |
|------|------|------|
| images | IMAGE（可选） | 连接后隐藏视频路径，改用上游图像批作为帧源 |
| audio | AUDIO（可选） | 连接后用此音频替代视频自带音轨 |
| fps | FLOAT（可选） | 外部帧率输入，当 images 输入连接时使用 |

### 输出端口

| 端口 | 类型 | 说明 |
|------|------|------|
| 当前图像 | IMAGE | 时间轴滑块所在位置的单帧图像 |
| 视频帧(选中) | IMAGE | 入点到出点之间（经帧间隔/强制帧率/裁剪处理后）的所有帧 |
| 帧率(浮点) | FLOAT | 输出帧率（浮点精度） |
| 音频 | AUDIO(VHS) | 选中范围内的音频（已对齐视频时间轴） |
| 视频信息 | ZYF_VIDEO_INFO | 复合信息包（见下方解包节点），包含分段计划元数据 |

## 2. zyf视频信息解包

将 zyf加载视频 输出的复合 `ZYF_VIDEO_INFO` 包拆分为独立端口，方便下游节点按需连线。

### 输入端口

| 端口 | 类型 | 说明 |
|------|------|------|
| 视频信息 | ZYF_VIDEO_INFO（必需） | 连接 zyf加载视频 的"视频信息"输出 |
| 视频帧 | IMAGE（可选） | 连接"视频帧(选中)"输出，用于提取首帧和尾帧图像。不连接时首帧/尾帧输出 1×1 空白占位 |

### 输出端口

| 端口 | 类型 | 说明 |
|------|------|------|
| 首帧图像 | IMAGE | 选中区间的第一帧图像 |
| 尾帧图像 | IMAGE | 选中区间的最后一帧图像 |
| 帧数(初始) | INT | 视频原始总帧数（入/出点之前） |
| 帧数(选中) | INT | 当前入/出点区间内的实际输出帧数 |
| 当前帧(初始) | INT | 当前帧在原始视频中的绝对帧号 |
| 当前帧(选中) | INT | 当前帧相对于入点的偏移（1-based） |
| 帧率(整数) | INT | 输出帧率（取整） |
| 宽度 | INT | 输出图像宽度（经缩放/裁剪/倍数处理后） |
| 高度 | INT | 输出图像高度（经缩放/裁剪/倍数处理后） |
| 文件名 | STRING | 视频源文件名 |
| 初始时长(秒) | FLOAT | 原始视频总时长（秒） |
| 选中时长(秒) | FLOAT | 选中区间时长（秒） |

## 3. zyf保存视频

将图像批编码为 MP4 视频文件，支持 H.264/H.265 编码、分段自动合并、元数据嵌入和灵活的目录结构。

节点右上角有 **折叠/展开按钮**（默认折叠），状态随工作流持久化记忆。

### 参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| 帧率 | FLOAT | 30.0 | 输出视频帧率（fps），范围 0.1-240，常用 24/30/60 |
| 文件名前缀 | STRING | AnimateDiff | 输出文件名前缀，支持子文件夹和模板变量（见下方说明） |
| 输出模式 | 下拉 | 保存预览 | 保存预览 / 仅预览 / 保存隐藏预览 |
| 保存元数据 | BOOLEAN | ✅ | 是否将 ComfyUI 工作流嵌入视频文件（拖回 ComfyUI 可恢复工作流） |
| 保留临时文件 | BOOLEAN | ❌ | 仅分段计划模式生效。关闭=合并完成后自动清除临时分段文件；开启=保留中间分段文件方便查看或自行重新合并 |
| 编码格式 | 下拉 | H264 | H264（兼容性好）/ H265（压缩率高）。切换时 CRF 自动同步到对应默认值 |
| 质量CRF | INT | 19 | 恒定质量因子：0=无损，18=视觉无损，23=ffmpeg默认，51=最差。H264 推荐 18-23，H265 推荐 20-28 |

### 文件名前缀说明

- 留空或填 `comfyui` → `output/comfyui_00001.mp4`
- 填 `wan2.2/999` → 自动创建子文件夹 `output/wan2.2/`，保存为 `999_00001.mp4`
- 填 `a/b/c/clip` → 嵌套子文件夹逐级自动创建
- 支持模板变量：`%width%` `%height%`（图像宽高）、`%year%` `%month%` `%day%`（日期）、`%hour%` `%minute%` `%second%`（时间）
- 同名前缀的已有文件不会被覆盖，counter 自动 +1

### 输出模式

| 模式 | 行为 |
|------|------|
| 保存预览 | 写入 output 目录 + 节点内显示视频预览 |
| 仅预览 | 编码到临时文件，仅用于节点内预览（不写入 output） |
| 保存隐藏预览 | 写入 output 目录，但节点不显示预览（节省界面空间） |

### 输入端口

| 端口 | 类型 | 说明 |
|------|------|------|
| 图片 | IMAGE（必需） | 要保存的图像批张量 `[N, H, W, C]`，RGB 浮点 `[0, 1]` |
| 音频 | AUDIO（可选） | 编码为 AAC 192kbps 与视频合流（以视频时长为基准） |
| 视频信息 | ZYF_VIDEO_INFO（可选） | 连接 zyf加载视频 的"视频信息"输出，用于**分段计划自动合并** |

## 4. 分段计划（高级功能）

分段计划解决长视频处理时显存不足的问题：将视频自动拆分为多段，利用 ComfyUI 队列逐段处理，最后自动合并为完整视频。

### 工作流程

1. 在 zyf加载视频 启用"分段计划"，设置分段长度（默认 81 帧，最低 41）
2. 将 zyf加载视频 的"视频信息"输出连接到 zyf保存视频 的"视频信息"输入
3. 点击 Queue Prompt 运行第一段
4. **自动排队**：每段处理完成后，后端通过 WebSocket 通知前端自动递增分段索引并排队下一段，无需手动点击
5. 最后一段完成时，zyf保存视频 自动将所有分段文件拼接为最终视频

### 分段规则

- **帧数守恒**：所有段帧数之和 = 选中区间总帧数
- **普通段（非最后段）**：保持 8N+1 格式（如 81、89、97…），兼容 WAN/LTX 等模型对帧数格式的要求
- **最后一段**：不要求 8N+1，可以是任意 ≥33 的整数（如 33/34/35/.../50/...），精确吃掉剩余帧
- **自动借帧**：若按等分切出的最后一段不足 33 帧，系统自动从倒数第二、第三…段"借帧"——被借段降到下一个 ≥33 的 8N+1 值，释放的帧数补给最后一段，直到最后一段 ≥33
- **分段临时目录**：`output/zyf_segment_temp/{batch_id}/`，重启 ComfyUI 后可继续未完成的分段任务

### 注意事项

- 分段处理利用 ComfyUI 队列循环实现（非 Python 内部 for 循环），每段独立执行、独立占用显存
- 开启"保留临时文件"可查看各段中间产物，关闭则合并完成后自动清理
- 分段批次编号（hidden widget）用于标识同一批次，修改此编号将重置自动索引

## 安装

1. 确保已安装 ComfyUI 及其依赖
2. 克隆到 custom_nodes 目录：

```bash
cd ComfyUI/custom_nodes
git clone https://github.com/dunklehohle/zyf-video.git zyf-video
```

3. 安装依赖：

```bash
cd zyf-video
pip install -r requirements.txt
```

> **注意**：确保 `ffmpeg` / `ffprobe` 在系统 PATH 中可用。Windows 用户可使用 `imageio-ffmpeg` 自带的 ffmpeg。

## 常见问题

**Q: 数值输出显示为 0？**
A: 确保 zyf加载视频 节点已连接（直接或间接）到某个输出节点，ComfyUI 才会执行该节点。

**Q: 视频加载失败？**
A: 检查 ffmpeg/ffprobe 是否在 PATH 中，以及视频格式是否支持（webm/mp4/mkv）。

**Q: 输出视频文件为空或极小？**
A: 检查 CRF 值和编码格式是否匹配。如果音频输入为空（无声音），请确保上游节点传递了有效的音频数据。

**Q: 分段计划只处理了第一段就停了？**
A: 确保已将 zyf加载视频 的"视频信息"输出连接到 zyf保存视频 的"视频信息"输入，自动排队依赖此连接传递分段元数据。

**Q: 分段后最终视频帧数不对？**
A: 检查控制台日志中各段帧数信息。系统保证帧数守恒（总帧数=各段帧数之和），最后一段自动借帧逻辑确保无截断。
